0 · 算法流水线总览

ABruijn 的设计哲学是「拓扑与序列解耦」:先用稀疏锚点把基因组的重复结构和读段重叠关系搞定(此阶段允许碱基全错),再对拼出的草图集中纠错——比对 / 纠错对象是整条草图而非每条读段,比 OLC 先纠错再组装便宜得多。点击下方任一阶段查看细节;两条指标线展示「错拼」在延伸阶段被压制、「碱基错误」在打磨阶段被消除。

数学细节:阶段划分与误差演化
  • 组装阶段(节点 2–5):输入读段错误率 ~13%(PacBio P6-C4)。产出草图的 错拼(misassembly)极少,但碱基错误率仍 ~13%——因为延伸只关心「哪些读段连贯」,不关心碱基对错。
  • 打磨阶段(节点 6–8):项链概率共识把错误率降到 0.003%;同核苷酸串专项似然再降 7 倍到 0.0004%(ECOLI 全基因组仅 19 个候选错误)。默认迭代 3 轮。
  • 对比 OLC 路线(HGAP/Canu):先逐读段纠错再组装,纠错计算量正比于全部读段×覆盖;ABruijn 只需对最终 ~5 Mb 草图做一轮多重比对。

1 · 从 de Bruijn 图到 A-Bruijn 图原文 Fig. 1

经典定义:把字符串沿路径铺开(顶点标 (k−1)-mer、边标 k-mer),再粘合同标签顶点得到 DB(String, k)。A-Bruijn 图的推广只有一处:粘合前的锚点不再必须是「所有 k-mer」,而可以是任选的词集合 V(不互相包含,长度任意、覆盖稀疏)。下面用论文的例子 String = CATCAGATAGGA(环形)逐步演示。试试两种模式,并悬停顶点看它的「孪生」顶点。

上:Path(String, ·) 环形路径(同色 = 同标签,将被粘合)。中:同标签顶点互相靠拢。下:粘合后的图。悬停顶点高亮同标签组。
为什么经典 DBG 在 SMS 读段上必死,而 A-Bruijn 图有活路?
  • DBG 的顶点集合是「读段中所有 k-mer」。错误率 13% 时,每个错误都制造 k 个假 k-mer 顶点:k 小 → 图被海量假顶点缠死;k 大 → 真顶点因覆盖不足而断裂。两头堵死。
  • Illumina 时代的救命稻草——bubble / tip 消除等图简化——其正确性依赖错误率 ≤ 1%;对 10%+ 错误率的复杂 bubble 全部失效(详见 SI1)。
  • A-Bruijn 图把「选哪些锚点」变成自由参数:ABruijn 用高频 (k,t)-mer(下一节),使假锚点极少;锚点稀疏意味着读段在图中只是骨架路径——这正是后面一切速度优势的来源。
  • 注意 DB(String,k) = AB(String, Σk−1):DBG 只是 A-Bruijn 框架的特例。A-Bruijn 图还涵盖断点图、质谱肽组装等更一般场景。

2 · 选固体串:高频 (k, t)-mer原文 Fig. 2

分类标准:在基因组中出现恰好一次的 k-mer 为「唯一」,多次为「重复」,不在基因组中的为「非基因组」(测序错误)。随机错误很难在多条读段里原样重复出现 t 次,所以「频率 ≥ t」是极强的基因组信号。ABruijn 定义 (k, t)-mer 为出现 ≥ t 次的 k-mer,并自动选 t:取使高频 k-mer 总数仍超过预估基因组长度的最大 t。拖动滑块,观察阈值带与右侧统计(直方图为按论文 Fig. 2 重建的示意数据,锚点数字与论文一致)。

ECOLI 数据集(E. coli K12,PacBio P6-C4,≈55×,k=15)。绿=唯一 / 红=重复 / 蓝=非基因组;虚线 = 基因组长度 4.64 Mb;阴影带 = 被选为固体的频率区间。悬停柱状图查看各频率组成。
阈值选择规则与参数直觉
  • 规则:对每个 t 统计 S(t) = 频率 ≥ t 的 k-mer 总数;取使 S(t) ≥ 基因组长度 G 的最大 t。直观:基因组自身贡献的高频 k-mer 数量以 G 为天然下界,一旦 S(t) 跌破 G,说明开始大量丢真 k-mer。
  • 论文中 t=7 时:4.1M 唯一 + 0.1M 重复 + 0.5M 非基因组(假阳性 ~11%,可容忍);t=8 时三者变为 3.9M / 0.1M / 0.3M。将自动 t 加 1 结果几乎不变(鲁棒)。
  • 非基因组 k-mer 在低频区(1–6 次)占绝大多数——它们是散乱错误;高频端的 0.5M 假阳性主要来自同核苷酸串中的相关错误(同一错误在覆盖堆叠中重复出现)。
  • k 的选择:k=15~25 均可,论文发现偏小的 k 略优(容错更高)。Xanthomonas 数据集自动选出 t=28(BLS)与 t=18(PXO),其余参数与 ECOLI 完全相同。

3 · jump-子路径:图上的重叠判定原文 Fig. 3

OLC 的瓶颈是全对全比对。ABruijn 的替代:两条重叠读段的骨架路径共享大量固体锚点(即使序列相似度只有 ~80%),于是把 A-Bruijn 图当预言机——一次扫描即可找出一条读段与所有其他读段的最长公共子路径。因为锚点间可能夹着「垃圾锚点」,公共子路径允许「跳」:相邻选中锚点在各自读段中的间隔 ≤ jump。用动态规划求最大跨度公共 jump-子路径,再以 minOverlap / maxOverhang 判重叠。拖动滑块看链在哪里断开。

共享锚点 读段 A 独有 读段 B 独有 ✕垃圾锚点(高频错误) 选中的公共 jump-子路径
数学细节:动态规划递推与悬突定义
  • 边 (v,w) 的权 shift(v,w) = 两锚点起点在读段中的位置差;路径 P 上两点间 P-距离 dP(v,w) = 沿途边权之和。
  • jump-子路径:顶点子序列 v₁…v_t,满足 d(vᵢ, vᵢ₊₁) ≤ jump;公共 jump-子路径须同时是 P₁、P₂ 的 jump-子路径(且顶点在两条路径中顺序一致)。
  • 递推(对每条与 P₁ 共享顶点的路径,一次扫描 P₁ 全部算完):
    spanjump(v) = maxw 为 v 在 P₁、P₂ 中的 jump-前驱 { spanjump(w) + dP₁(w, v) }
    其中 jump-前驱 = 在该路径中先于 v 出现且 d ≤ jump 的顶点。SI1 给出更快的启发式。
  • 右悬突 = min(Pathjump 终点到 P₁、P₂ 各自末端的距离);左悬突对称(到起点)。判定重叠:span ≥ minOverlap 且左右悬突 ≤ maxOverhang。论文 SI2 给出参数的经验范围;本示例 jump=1000 时公共子路径含 50 顶点、跨度 6,714 bp(悬突 425/434),此处为便于观看用了 9 个锚点的简化版。
  • 第二个数据集展示假阳性来源:同一重复的两个拷贝共享全部保守锚点 → 判为「重叠」。这类假重叠由后续的 most-consistent 选择与支持图聚类兜底(第 4、5 节)。

4 · 路径延伸:选「最一致」读段原文 Fig. 4 (Top)

从短读长组装器(exSPAnder / SPAdes 系)借来 path extension 范式:维护一条 growing path,每步从候选集 Paths(与其重叠的读段)中挑一条向右延伸。难点是候选中混着三种坏读段:嵌合(真前缀+假尾巴)、假重叠(来自基因其他位置)、过短。ABruijn 的筛选器:支持关系——若 P₁、P₂ 重叠且公共部分终点到 P₁ 末端的距离更短,称「P₁ 被 P₂ 支持」(即 P₂ 延伸得更远)。取 Support = min(被支持数, 支持数) 最大者为 most-consistent:嵌合读段能支持很多人却几乎不被任何人支持,过短读段反之,min() 一石二鸟。

悬停任一候选读段:紫色箭头 = 「它支持的读段」(它延伸更远),绿色箭头 = 「支持它的读段」。虚线红段 = 嵌合读段的假尾巴。
实现要点
  • 一条 contig 拼完后,ABruijn 把所有读段比对回该 contig,用尚未使用过的读段迭代构建其余 contigs;向右延伸停止则尝试向左。
  • 支持关系的判定复用第 3 节的 jump-子路径机器(两条路径的 Pathjump + 悬突比较),因此「A-Bruijn 框架对重叠检测比 de Bruijn 框架更不敏感」这一性质同样适用于支持计数。
  • 平局任意打破;被选中的读段随后从候选池移除,避免循环延伸。

5 · 支持图聚类:检测读段是否落在重复里原文 Fig. 4 (中/下) + Fig. 5

exSPAnder 在 de Bruijn 图里能直接「看见」分支(重复)结构;A-Bruijn 图看不见。ABruijn 的替代:纯从候选读段间的支持关系拓扑反推。对候选集构建支持图 G(边 v→w 表示 v 被 w 支持),取传递闭包 G*,然后迭代聚类:取最大入度顶点,若入度 > 1,把它连同全部前驱移除为一簇。1 簇 → 读段末端不在重复里;≥2 簇 → 末端在重复里(簇数 ≈ 重复倍数 m)——来自不同拷贝的读段互不支持,所以彼此不连通。切换两个场景,逐簇观看聚类过程。

实线 = 支持图 G 的边;虚线 = 传递闭包 G* 新增的边;悬停顶点查看其 G* 入度/出度。论文实测:ECOLI 3.2%、BLS 6.4% 的读段末端落在重复里。
决策规则(延伸时如何用聚类结果)
  • growing path 不停在重复里:选一条 (i) 末端不在重复 (ii) most-consistent(入度、出度都大)的候选——同时排除嵌合与假重叠。
  • growing path 停在重复里:排除所有「起点在重复里」的候选(它们可能跳去其他拷贝),在剩余候选中选 most-consistent;若无则停止延伸(等后续 unbridged 机制或留作断点)。
  • 聚类用 Floyd–Warshall 求传递闭包;默认入度阈值 = 1。场景 B 中蓝色簇恰好 5 条、红色簇 3 条,对应倍数 2 的重复两侧延伸——与论文 Fig. 4(下)「read 8 入度最大、揭示 4 个前驱」的描述一致。
  • 这一整套启发式(支持图 + 聚类 + 决策规则)是 ABruijn 为「看不见局部重复结构」付出的代价——Flye 后来用「先乱拼、再建图」把整个问题绕开了。

6 · 纠错:迷你比对 → 项链共识 → 同核苷酸串原文 Fig. 6

草图结构对了,但每个碱基都可能错。纠错分三步:① 把全基因组多重比对切成成千上万个 ≈30 nt 的迷你比对(用「固体区域 → 地标」划分,避免错位段污染共识);② 对每条项链跑概率共识;③ 对同核苷酸串(占 E. coli 基因组 46%、PacBio 的老大难)换用专门的似然函数。三个子演示对应这三步。

6a · 固体区域、地标与项链的划分Fig. 6 左/右

25 bp 草图片段 × 6 条读段的自制演示比对(结构仿照 Fig. 6):琥珀=替换、红=缺失、蓝=插入;统计行实时计算;(α,β)-固体 4-mer 行决定固体区域;紫色 ◆ = 地标(避开同核苷酸串);色带 = 项链划分。悬停单元格看逐列数值。
定义:(α,β)-固体 l-mer 与选地标
  • 列统计:Cov(i) = Match(i)+Sub(i)+Del(i);Ins(i) = 参考列 i 与 i+1 之间非参考列的插入总数。match rate = Match/Cov,insertion rate = Ins/Cov。
  • 草图中 l-mer 的局部 match rate = 其覆盖位置上 match rate 的最小值;局部 insertion rate = insertion rate 的最大值。(α,β)-固体:前者 > α 且后者 ≤ β。论文取 l=10、α=0.8、β=0.2(ECOLI 草图得 139,585 个固体区域);演示用 l=4 便于展示。
  • 连续固体 l-mer 构成固体区域;每个区域内选一个地标(刻意避开同核苷酸串),相邻地标间的读段片段构成迷你比对,平均仅 ≈30 nt——短到纠错又快又准。
  • 为什么不能用固定长度切?BLASR 比对不可靠:读段上对齐到第 i 段的区域可能实际来自 i±1 段或另一重复拷贝(错位段),共识就被污染。固体区域相当于「高置信锚排」,把基因组切成天然对齐的小格。插入高发区(如演示中 16–17 列)自动落进项链内部,由共识算法处理。

6c · 同核苷酸串专项似然SI 4 / 正文 8.5 节

论文实例:项链片段 Segments = {5A, 6A, 6A, 7A, 6A1C}。通用似然在同核苷酸串长度估计上失效;专项似然用「run 长度 → 读段观测」频率表(如 run AAAAAAA 对上读段 AATTACA 记作 4A3X)。该表跨数据集、跨参考、甚至跨化学版本(P6-C4 vs P5-C3)几乎不变。
整体纠错流程小结
  • BLASR 全读段比对回草图 → 合并成全基因组多重比对 → 按「固体区域/地标」切项链 → 每条项链概率共识(错误率 → 0.003%)→ 同核苷酸串专项似然(→ 0.0004%,ECOLI 全基因组 19 个候选错误)。
  • 默认重新比对 + 打磨迭代 3 轮;SI6 说明再降 ~20% 的后处理。ECOLI 全程:组装 ≈8 min + 打磨 ≈36 min,内存 2 GB。
  • 与 Quiver 的关系:Quiver 用原始机器信号(HDF5 pulse),ABruijn 用碱基级统计——所以 ABruijn 不挂 Quiver 也能到同等精度(Table 1:19 vs CANU 裸组装 637)。

8 · 承上启下:ABruijn 留下了什么问题?

ABruijn 证明了「de Bruijn 图一系方法可以组装长错误读段」,但它有三个结构性代价——它们正是 2019 年 Flye(同一团队)要解决的东西。

ABruijn 的代价根源Flye 的解法
逐读段延伸,选路慢且需谨慎校验要保证每条 contig 都是基因组 tour 的正确子路径干脆不保证:随机游走生成「错的」disjointigs,再从它们重建准确的重复图
支持图 / 聚类等一整套启发式A-Bruijn 图看不见局部重复结构显式构建重复图(assembly graph),重复结构一目了然
只输出 contigs,无重复刻画路径延伸到分支处就停,图从未显式出现输出重复图本身:可用于解 unbridged repeats、分析节段重复(SD)、辅助 finishing
