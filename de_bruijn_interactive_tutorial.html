1为什么组装需要图？

测序仪无法一次读完整条染色体，只能产出大量短片段（reads）——短读长平台每条只有几十到几百 bp， 长读长平台（PacBio / Nanopore）虽能到几 kb 甚至更长，但错误率高达 5–15%。 基因组组装就是把这些碎片拼回完整基因组的"拼图问题"。

reads→ 切成 k-mers→ 构建 de Bruijn 图→ 欧拉路径→ 基因组序列

为什么"拼 reads"会变成"找路径"？——两种建模方式

组装要同时满足两个约束：① 每片恰好用一次——少一片就缺序列，多用一片就重复； ② 相邻的片要衔接——后一片的开头与前一片的结尾重叠。 "每片恰好用一次 + 依序衔接"天然是一个图上的路径问题：把"片"画成图、把"衔接"画成边，一种合法的拼法就是一条路径。 整个领域的分野在于——你把什么当作"片"：

建模 A：reads 当顶点（重叠图 → 哈密顿路径）

例：基因组 ATGGCG，两条不等长 reads：r1 = ATGGC(5bp)、r2 = GGCG(4bp)

ATGGC ── 重叠 "GGC"(3bp) ⟶ GGCG

顶点 = read；边 = 足够长的后缀-前缀重叠。
"每条 read 恰好用一次" ⟺ 每个顶点恰好访问一次 = 哈密顿路径。
按重叠衔接拼回：ATGGC + GGCG 去重叠 = ATGGCG ✓

找这样的路径没有任何局部判据可用，只能全局搜索——判定问题是 NP-complete，规模一大只能靠启发式（第 7 节有交互演示）。

建模 B：k-mer 当边（de Bruijn 图 → 欧拉路径）

同一组 reads，切 k-mer（k = 4）：ATGG TGGC GGCG

(ATG)─ATGG→(TGG)─TGGC→(GGC)─GGCG→(GCG)

顶点 = (k−1)-mer；边 = k-mer（reads 只是证据，图中真正的对象是 k-mer）。
"每个 k-mer 恰好用一次" ⟺ 每条边恰好走一次 = 欧拉路径。
沿路径每走一步追加一个字符：ATG + G + C + G = ATGGCG ✓

为什么"用完所有边"就等于重建基因组？在无重复的基因组里每个 k-mer 位置唯一，reads 只是它的随机采样——把观察到的 k-mer 边不重不漏地走一遍，就是"把基因组抄一遍"。

两种建模，一字之差：同样是"每片恰好用一次"，把片放在顶点上 → 哈密顿路径（NP-hard，只能启发式）； 把片放在边上 → 欧拉路径（只需检查每个顶点的入度/出度是否平衡，Hierholzer 算法 O(E) 直接构造解）。 把对象从顶点挪到边上，NP-hard 立刻变多项式——这是 Pevzner、Tang 与 Waterman 在 PNAS 2001 提出欧拉组装（EULER）的核心洞察， 也是 Velvet、ABySS、SPAdes 等短读长组装器的地基。一步步看 de Bruijn 图如何从 reads 建起来 → 第 3 节； 两种路径的完整对比与交互演示 → 第 7 节。

2动手构建：从字符串到 de Bruijn 图

边视角（edge-centric）定义：节点是所有 (k−1)-mer；从节点 u 到 v 有一条边，当且仅当 存在 k-mer 其前 k−1 个字符等于 u、后 k−1 个字符等于 v——也就是说每条边就是一个 k-mer。 组装 = 找一条恰好走过每条边一次的路径（欧拉路径），沿途每走一步追加该 k-mer 的最后一个字符。

💡 试一试：① 悬停节点 / 边，查看序列与覆盖度；② 换成预设"含精确重复"——注意黄色分支节点和两条平行的重复边（×2）， 此时欧拉路径不再唯一；③ 把 k 调大，观察重复带来的分叉何时消失。

→ 真实组装的输入不是一条完整字符串，而是不等长的 reads——第 3 节把构建过程一步一步拆开演示。

4模拟真实组装：reads、覆盖度与错误

真实数据里我们没有基因组，只有带错误、随机采样的 reads。下面从一条"秘密基因组"模拟测序： 以给定覆盖度（平均每个碱基被测到几次）随机抽取 reads，并按错误率引入单碱基替换，然后完全从 reads 建图、走欧拉路径。

  • 🔴 死端 tip：测序错误产生的低覆盖 k-mer 无路可走，形成红色死胡同——真实组装器会做"tip 修剪"；
  • 🟡 分支：来自重复序列或杂合变异；
  • 🟣 图断裂：覆盖度不足或 k 过大时，reads 之间缺少连接，欧拉路径只能走完一个连通块。
💡 试一试：① 错误率 0%、覆盖度 ≥3× —— 应能完美重建基因组； ② 把错误率拉到 6% —— 观察红色 tips 如何污染拼出的序列，再勾选"过滤低覆盖边"看是否救回来； ③ 覆盖度降到 1×~2× —— 观察图断裂警告。

5重复序列与 k 的选择

重复是组装的头号敌人。当重复长度 ≥ k 时，两个副本的 k-mer 完全相同，在图中被合并成同一批节点/边—— 路径在这里分叉（黄色节点），欧拉路径不再唯一，可能产生嵌合（chimeric）组装。 增大 k 可以让副本分离，但 k 太大又会提高对覆盖度和读长的要求。亲手找这个平衡点：

6A-Bruijn 图：允许"相似"的广义 de Bruijn 图

de Bruijn 图只合并完全相同的 k-mer，一旦重复副本之间有突变（真实生物的重复家族几乎总是如此），副本就无法折叠。 A-Bruijn 图（Pevzner & Tang, PNAS 2004；Raphael, Zhi, Tang & Pevzner, JCB 2004；A = Assembling）把"合并规则"泛化：

  1. 把整条序列拆成位置 k-mer（positional k-mer = k-mer + 它的位置）；
  2. 相邻位置之间连边；
  3. 按某个等价关系 ξ（合并规则）把位置 k-mer 粘合成节点——de Bruijn 图取 ξ = "序列完全相同"； A-Bruijn 图允许 ξ = "序列相似"（例如海明距离 ≤ d）。

7哈密顿路径 vs 欧拉路径：一字之差，难度天壤

第 1 节的对比表说过：重叠图（OLC）上的组装是哈密顿路径问题，de Bruijn 图上的组装是欧拉路径问题。 这两个"路径"只差一个字——一个访问每个点一次，一个走过每条边一次——计算难度却有云泥之别。本节把它们放在一起，亲手感受。

哈密顿路径（Hamiltonian path）欧拉路径（Euler path）
要求访问每个顶点恰好一次走过每条边恰好一次
起源哈密顿的"环游世界"棋盘游戏（Icosian game，1857）哥尼斯堡七桥问题（欧拉，1736）——图论的起点：4 块陆地度数全为奇数，所以不重复地走完七座桥不可能
存在性判定没有简单的局部条件；判定问题是 NP-complete（Karp 1972 年"21 个 NP 完全问题"之一）图连通，且奇度顶点数为 0（回路）或 2（路径）——数一下度数即可，O(E)
求解最坏要枚举 ~n! 种访问顺序；最好的精确算法也是指数级（如 2ⁿ·poly(n)）Hierholzer 算法：线性时间 O(E) 直接构造解
对应到组装重叠图：节点 = read，边 = 重叠 → 组装 = 哈密顿路径de Bruijn 图：节点 = (k−1)-mer，边 = k-mer → 组装 = 欧拉路径
为什么"边"和"点"一字之差，难度就天差地别？ 欧拉路径只依赖局部信息——每个顶点的入度/出度。走过的边用掉一条，度数随之减一；只要出发时图是"平衡"的， 每一步都有据可循，走不出去就回头接环（Hierholzer 的核心想法）。哈密顿路径则要求全局选择： "下一个访问谁"会改变之后所有的选项，没有任何局部度数条件能保证全局不重不漏——只能回溯搜索。 Pevzner–Tang–Waterman（PNAS 2001）的关键洞察正是：换一种图的表示，把 k-mer 放到边上，NP-hard 的组装立刻变成多项式的欧拉问题——选择正确的表示，就是选择正确的计算复杂度。

诚实的补充：真实组装器都不会真去枚举 n!——OLC 组装器用贪心/启发式（"每次接最长的重叠"），大多数情形表现良好， 但 NP-complete 是关于最坏情形的论断，无法给出保证。同样，真实的 de Bruijn 组装器还要对付重复与分支（见第 5、6 节）， 欧拉路径只是给了它一个"保证能算完"的骨架。
